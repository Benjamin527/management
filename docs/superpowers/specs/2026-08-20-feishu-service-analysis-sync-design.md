# 2026 年飞书服务数据分析与同步设计

## 目标

把飞书多维表格中的 2026 年客户服务记录同步到售后系统，用于管理层分析、客户下钻和服务记录查询。飞书保持唯一录入和修改入口；系统只做同步、标准化、展示和分析，不向飞书回写。

## 已验证的数据源

- Base App Token：通过服务端环境变量配置。
- 数据表：`tblczuC0hyPSnOMj`。
- 链接中的 `view_id=vewQx72054` 只是飞书视图筛选，不作为同步边界。
- 代码通过飞书开放平台应用身份读取，已验证可以分页访问字段和记录接口。
- 整表当前共 4,075 条记录、176 个客户，时间范围从 2024-02-18 到 2026-08-20。
- 系统只保存和分析“开始日期”属于 2026 年的记录。

应用 ID、应用密钥和访问令牌不得写入 Git、前端代码、日志或接口响应。应用密钥只存放在服务器 `.env` 中，并在正式上线后轮换一次。

## 范围

本期包含：

- 2026 年数据首次全量导入。
- 每日最近 7 天增量同步和失败补偿。
- 手动同步最近 7 天、手动重建 2026 全年数据。
- 服务分析总览、趋势与分布图表。
- 服务记录明细筛选、分页和详情抽屉。
- 客户中心中的服务次数、未完成数量和高频问题。
- 同步状态、失败原因和数据质量提示。

本期不包含：

- 在系统内新建服务记录。
- 修改飞书记录或回写状态、结论。
- 飞书事件订阅和秒级实时同步。
- 2025 年及更早的历史数据分析。
- 使用当前飞书视图作为数据过滤条件。

## 方案选择

采用“MySQL 查询镜像 + 每日滑动窗口同步”。不采用页面实时代理飞书接口，因为实时代理会增加页面延迟、受飞书限流与可用性影响，也不利于跨客户、跨月份聚合。不采用第一期事件订阅，因为一天一次的数据新鲜度已经满足需求，事件订阅会增加回调验签、重放和顺序处理复杂度。

### 服务端组件

1. `FeishuAuthService`
   - 使用 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET` 获取 `tenant_access_token`。
   - 在内存中缓存令牌，并在过期前刷新。
   - 不输出令牌和密钥。

2. `FeishuBaseClient`
   - 使用 `FEISHU_BASE_APP_TOKEN` 和 `FEISHU_SERVICE_TABLE_ID` 请求记录接口。
   - 不传 `view_id`。
   - 使用记录搜索接口在飞书服务端按“开始日期”过滤，只拉取 2026 年或本次增量窗口内的数据。
   - 处理 `page_token`，直到读取完整查询结果。
   - 对限流和临时网络错误执行有限次数退避重试。

3. `ServiceRecordMapper`
   - 把飞书单元格值转换成稳定的内部类型。
   - 保留飞书原始分类，同时生成统计使用的标准分类。
   - 使用飞书 `record_id` 作为同步幂等键，使用“服务记录ID”作为用户可见编号。

4. `ServiceRecordSyncService`
   - 负责首次导入、每日同步、失败补偿和手动重建。
   - 记录每次同步的范围、状态、读取数、新增数、更新数、删除数、失败数和错误摘要。

5. `ServiceAnalysisService`
   - 只查询 MySQL。
   - 提供 KPI、月度趋势、状态分布、问题类型、反馈类型、来源、部署形态、客户排行和工程师统计。

## 同步策略

### 首次同步

- 不传视图 ID，在飞书记录搜索接口中设置 `开始日期 >= 2026-01-01 00:00:00` 且 `< 2027-01-01 00:00:00`。
- 服务端收到记录后再次校验年份，非 2026 年记录不得写入 MySQL。
- 按飞书 `record_id` 执行 upsert。
- 首次同步完成前，旧的本地分析数据继续可读；同步全部成功后再把本次运行标记为成功。

### 每日同步

- 默认每天 Asia/Shanghai 时区凌晨 02:00 执行。
- 业务窗口为包含今天在内的最近 7 个自然日，即 `[今天 - 6 天 00:00, 明天 00:00)`。
- 实际请求额外向前重叠 1 天，即 `[今天 - 7 天 00:00, 明天 00:00)`，避免零点、时区和任务执行边界漏数。
- 同步返回记录按 `record_id` upsert，覆盖可能变化的状态、结论、处理人和满意度。

### 失败补偿

- 保存最后一次成功同步时间 `lastSuccessfulAt`。
- 如果距离最后成功同步超过 7 天，下次窗口自动扩展到 `lastSuccessfulAt` 前 1 天。
- 窗口最早不早于 2026-01-01。
- 只有所有分页都成功后，才更新 `lastSuccessfulAt`。
- 某一页失败时，本次运行标记失败；不得根据不完整结果判断记录已删除。

### 手动同步

- “立即同步最近数据”：执行同样的滑动窗口和失败补偿逻辑。
- “重新同步 2026 全年”：重新拉取 2026 年全部记录并 upsert，用于纠错和灾难恢复。
- 两个操作仅允许 `ADMIN` 或 `MANAGER` 执行。
- 同一时间只允许一个同步任务运行。

### 删除处理

- 最近窗口同步成功后，如果本地窗口内某条记录未出现在飞书结果中，将其软删除。
- 全年重建成功后，对 2026 年范围执行完整缺失比对。
- 分页未完成或同步失败时不执行缺失比对。

## 数据模型

新增 `FeishuServiceRecord`，与现有手工 `ServiceIssue` 分开，避免把只读分析数据和系统内工单流转逻辑混在一起。

主要字段：

| 系统字段 | 飞书字段 | 用途 |
|---|---|---|
| `externalRecordId` | 飞书 `record_id` | 唯一同步键 |
| `serviceRecordNo` | 服务记录ID | 列表可见编号 |
| `startDate` / `endDate` | 开始日期 / 结束日期 | 年份过滤与趋势统计 |
| `customerName` | 客户名称 | 客户分析和关联 |
| `questionerRole` | 提问者和角色 | 详情展示 |
| `sourceType` | 来源类型 | 渠道分析 |
| `feedbackTypeRaw` | 反馈类型 | 原始值追溯 |
| `feedbackTypeNormalized` | 反馈类型标准值 | 聚合统计 |
| `issueTypeRaw` | 问题类型 | 原始值追溯 |
| `issueTypeNormalized` | 问题类型标准值 | 聚合统计 |
| `deploymentType` | 部署形态 | 部署形态分析 |
| `ticketId` | 工单ID | 外部工单关联 |
| `summary` | 反馈内容（简要描述） | 列表与详情 |
| `conclusion` | 结论（简要描述或链接） | 详情展示 |
| `satisfaction` | 客户满意度 | 满意度统计 |
| `sourceStatus` | 状态 | 保留飞书原始状态 |
| `normalizedStatus` | 状态标准值 | KPI 与筛选 |
| `firstLineEngineer` | 一线工程师 | 工作量分析 |
| `secondLineEngineer` | 二线工程师 | 处理链路 |
| `thirdLineEngineer` | 三线产研 | 升级统计 |
| `keyIssue` | 重点问题 | 重点问题筛选 |
| `submittedByName` / `submittedByOpenId` | 提交人 | 追溯 |
| `submittedAt` | 提交时间 | 录入趋势 |
| `rawFields` | 完整字段 JSON | 兼容未来字段变化 |
| `syncedAt` | 系统生成 | 数据新鲜度 |
| `deletedAt` | 系统生成 | 软删除 |

`Customer` 表按客户名称匹配。同步遇到不存在的客户时自动创建基础客户档案；不会覆盖客户中心已有的行业、级别、负责人等人工维护字段。

## 分类和状态标准化

原始值始终保留。标准化只影响统计：

- `已解决` → `RESOLVED`
- `已关闭` → `CLOSED`
- `跟进中` → `IN_PROGRESS`
- `待回复` → `WAITING_REPLY`
- `已提交飞书项目` → `ESCALATED`
- 空状态 → `UNKNOWN`

已发现的重复分类合并：

- `Datakit问题`、`DataKit 问题` → `DataKit 问题`
- `Func问题`、`Func 问题` → `Func 问题`
- 其他未经确认的分类不自动合并，只做空格和大小写规范化后保留。

## API 设计

### 分析

- `GET /api/service-analysis/summary?year=2026`
  - 返回核心 KPI 和数据新鲜度。
- `GET /api/service-analysis/trend?year=2026&dimension=status`
  - 返回 12 个月趋势。
- `GET /api/service-analysis/distribution?year=2026&dimension=issueType`
  - `dimension` 支持 `status`、`feedbackType`、`issueType`、`sourceType`、`deploymentType`、`engineer`。
- `GET /api/service-analysis/customers?year=2026&limit=10`
  - 返回客户服务量、未完成量和高频问题。

### 明细

- `GET /api/service-records`
  - 支持 `keyword`、`customer`、`status`、`sourceType`、`feedbackType`、`issueType`、`deploymentType`、`engineer`、`dateFrom`、`dateTo`、`page`、`pageSize`。
  - 强制把日期限制在 2026 年。
- `GET /api/service-records/:id`
  - 返回详情和原始飞书记录地址。

### 同步管理

- `GET /api/service-sync/status`
- `POST /api/service-sync/run`，请求体 `{ "mode": "recent" }`
- `POST /api/service-sync/run`，请求体 `{ "mode": "full-year" }`

同步接口返回任务已接受，不保持长 HTTP 请求等待；页面轮询状态接口展示进度。

## 页面设计

### 2026 服务分析

核心 KPI：

- 2026 服务记录总量。
- 当前待回复。
- 当前跟进中。
- 已升级飞书项目。
- Bug 数和占比。
- 已解决/已关闭占比。
- 已服务客户数量。

核心图表：

- 2026 月度服务量趋势，按状态堆叠。
- 反馈类型分布。
- 问题类型 Top 10。
- 来源渠道分布。
- 部署形态分布。
- 客户服务量 Top 10，同时展示未完成数量。
- 工程师处理量和升级三线产研数量。

所有 KPI 和图表支持点击下钻到明细列表，并自动携带对应筛选条件。

### 服务记录明细

- 默认显示 2026 年最近记录。
- 状态页签：全部、待回复、跟进中、飞书项目、已解决、已关闭、数据缺失。
- 支持客户、时间、来源、反馈类型、问题类型、部署形态和工程师组合筛选。
- 列表展示：服务记录ID、客户、反馈摘要、来源、反馈类型、问题类型、状态、一线工程师、开始日期。
- 点击记录打开详情抽屉，展示处理结论、三级处理链路、满意度、提问者角色和飞书原记录链接。
- 不显示本地“新建服务问题”；替换为“打开飞书服务表”。

### 客户中心

- 客户行增加 2026 服务次数、当前未完成数和最近服务日期。
- 客户详情增加月度趋势、高频问题类型和最近服务记录。

### 同步状态

- 顶部显示最近成功时间和当前数据截至日期。
- 管理员可看到读取、新增、更新、删除和失败数量。
- 同步失败时显示可执行的错误摘要，不显示令牌、请求头或应用密钥。

## 数据质量处理

当前整表中存在大量未填写字段，因此分析页面必须标注数据覆盖率：

- 一线工程师缺失 2,102 条，工程师排行不能解释为完整工作量。
- 客户满意度仅填写 35 条，不能把均分解释为整体客户满意度。
- 工单ID仅填写 449 条。
- 重点问题仅填写 30 条。
- 反馈类型存在历史命名重复。
- 日期字段以自然日为主，不能据此计算真实首次响应时间或精确处理时长。

页面在相关图表旁显示覆盖率，避免产生错误管理结论。

## 错误与安全

- 鉴权失败：保留上次成功数据，记录同步失败，不清空数据库。
- 分页失败：整次同步失败，不更新水位、不执行删除比对。
- 单条字段异常：保留 `rawFields`，记录失败项，其余记录继续同步；运行结果显示失败数。
- 分类未知：保留原值，标准值归入 `OTHER`，不丢弃记录。
- 数据库失败：事务回滚当前批次，任务失败并可重试。
- 同步接口只允许 `ADMIN` 和 `MANAGER`。
- 应用密钥仅存在服务器环境变量中。

## 测试与验收

### 自动测试

- 令牌缓存和刷新。
- 飞书分页读取和限流重试。
- 2026 年过滤、7 天窗口、1 天重叠和失败补偿。
- `record_id` 幂等 upsert。
- 状态和重复分类标准化。
- 分页失败时不推进水位、不软删除。
- 分析聚合和筛选条件。
- 管理权限和同步并发锁。
- 页面 KPI、筛选下钻、空状态和错误状态。

### 验收标准

- 首次同步后，本地 2026 年记录数与飞书 API 的同条件结果一致。
- 重复执行同步不产生重复记录。
- 修改最近 7 天的一条飞书记录后，下一次同步能更新本地状态和结论。
- 模拟连续 10 天同步失败后，恢复运行能自动扩大窗口并补齐数据。
- 飞书接口不可用时，分析页面仍能读取上次成功数据并显示数据时间。
- 服务分析页面和明细列表只展示 2026 年数据。
- 页面不提供本地工单写入入口。
