# 飞书售后交接档案与客户中心布局优化设计

## 1. 背景与目标

售后交接资料的事实源为飞书多维表格：

- Wiki 节点：`KGmiw4Zb7i6arxkKdhJcBIDFn1b`
- Base app token：`V3eEbIUMYaGYrMsunaOcDWfinpc`
- 数据表：`tblMBCnwUUfxgnLi`
- 表名：`交接信息收集表`

经企业自建应用身份验证，当前应用可以读取该表的 20 个字段和 39 条记录。系统现有客户中心有 96 家客户。本次目标是：

1. 以飞书表为售后交接资料的唯一事实源，在系统中建立只读镜像。
2. 保留现有 96 家客户，不因未出现在交接表中而删除。
3. 将 39 条交接资料按客户名称关联到客户档案，并明确展示已交接、待交接和待关联状态。
4. 在客户中心和客户详情中有层次地展示交接信息、遗留问题和服务记录。
5. 修复整个页面随长列表滚动、弹窗出现在页面下方等布局问题，并统一修复同类浮层问题。
6. 对源表中的账号、密码等敏感信息进行默认脱敏和管理员受控查看。

## 2. 已确认的数据范围

源表字段包括：

- 客户名称
- 部署方式、部署清单、SAAS 站点
- 功能使用统计
- 日志采集、日志采集补充
- APM 接入探针、APM 接入补充
- RUM 应用接入、RUM 接入方式补充
- 非标操作或特别开发功能及其副本字段
- 交接人、交接时间、交接状态
- 是否解决过重要或高频问题
- 有无遗留问题
- 沟通渠道、对接人信息

当前数据特征：

- 39 条记录均有客户名称、部署方式、交接人、交接时间和功能使用统计。
- 交接状态以“审核通过”为主，同时存在“待审核”“打回”和空值。
- 多选字段由字符串数组表示；人员、富文本和链接字段由对象数组表示；日期为毫秒时间戳。
- “部署清单”等长文本中可能包含账号、密码、内部地址等敏感内容，不能通过普通客户列表或通用详情接口直接暴露。
- 源表当前记录量小，适合每日完整校准，不需要引入复杂的增量游标。

## 3. 方案选择

采用“独立售后交接镜像 + 客户关联”方案。

不把 20 个飞书字段直接塞入 `Customer`，避免客户核心模型被外部表结构绑定；也不在页面请求时实时代理飞书，以免页面性能、可用性和筛选能力受飞书接口影响。

系统继续以 `Customer` 表承载统一客户身份，新增独立交接档案模型承载飞书镜像。两者通过规范化客户名称自动关联，无法安全匹配的记录保留在待关联队列中。

## 4. 数据模型

### 4.1 售后交接档案

新增 `FeishuHandoffProfile`，建议字段如下：

- `id`
- `externalRecordId`：飞书记录 ID，唯一
- `customerId`：可空，关联现有客户
- `customerName`：源表客户名称
- `normalizedCustomerName`：用于精确规范化匹配
- `deploymentType`
- `deploymentChecklistMasked`：脱敏后的部署清单
- `saasSites`
- `featureUsage`
- `logCollection`
- `logCollectionNotes`
- `apmProbes`
- `apmNotes`
- `rumApps`
- `rumNotes`
- `customFeatures`
- `handoffPeople`
- `handoffAt`
- `handoffStatus`
- `importantIssues`
- `legacyIssues`
- `communicationChannel`
- `contactInfo`
- `rawFieldsMasked`：经过敏感信息处理的完整源字段
- `sourceCreatedAt`
- `sourceUpdatedAt`
- `syncedAt`
- `deletedAt`
- `createdAt`
- `updatedAt`

多选值使用 JSON 数组存储，避免丢失组合信息；长文本使用 `Text`。源表中全空的副本字段仍保留在脱敏后的原始字段中，但不单独建立业务列。

### 4.2 敏感数据

源表敏感原文不写入普通镜像字段。同步时识别账号、密码、令牌、密钥等内容：

- 普通展示只保存和返回脱敏版本。
- 必须保留的敏感原文单独加密存储在 `FeishuHandoffSecret` 中，不进入列表、客户详情或通用日志。
- 加密密钥只保存在服务器环境变量中，不进入数据库、源码或 Git。
- 只有 `ADMIN` 角色可以调用单独的查看接口。
- 每次查看写入 `SensitiveAccessAudit`，记录用户、客户、字段、时间和请求来源，不记录秘密内容本身。
- API 返回值设置禁止缓存响应头，前端关闭浮层后立即丢弃明文状态。

### 4.3 同步运行记录

新增 `HandoffSyncRun`，记录状态、读取数、创建数、更新数、取消关联数、软删除数、失败数和错误摘要，用于页面状态展示和故障排查。

## 5. 同步与关联

### 5.1 飞书应用身份

复用现有服务器配置的企业自建应用：

- 使用 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET` 获取 `tenant_access_token`。
- 不依赖任何个人用户授权。
- 新增交接表独立配置，不覆盖服务记录表配置。

建议新增环境变量：

- `FEISHU_HANDOFF_BASE_APP_TOKEN`
- `FEISHU_HANDOFF_TABLE_ID`
- `FEISHU_HANDOFF_BASE_URL`
- `FEISHU_HANDOFF_SYNC_CRON`
- `HANDOFF_SECRET_ENCRYPTION_KEY`

### 5.2 同步策略

- 首次执行完整同步，读取全部记录并分页处理。
- 每天北京时间 02:30 完整校准一次，与服务记录同步错峰。
- 每次同步以 `externalRecordId` 幂等 upsert。
- 仅在整次拉取成功后处理源表删除：本地缺失记录标记 `deletedAt`，不物理删除。
- 单条字段解析错误不会阻断其他记录，但会计入失败数并留下脱敏摘要。
- 同一时间只允许一个交接同步任务运行。

### 5.3 客户名称关联

规范化仅处理安全、可解释的差异：首尾空格、连续空白、全半角括号和英文大小写。

- 规范化后唯一精确匹配：自动关联。
- 无匹配：进入“待关联”，保留源记录，不自动创建客户。
- 多个候选：进入“待关联”，不猜测。
- 管理员可以手动指定客户；手动关联优先于下一次自动匹配。
- 未出现在交接表中的现有客户继续保留，并显示“待交接”。

## 6. API 设计

### 6.1 客户列表

扩展 `GET /api/customers`：

- 新增 `handoffState`：`ALL | HANDED_OVER | PENDING | UNMATCHED`
- 新增 `handoffStatus`
- 新增 `deploymentType`
- 新增 `hasLegacyIssues`
- 列表返回精简的 `handoffSummary`，不返回长文本、原始字段或敏感内容。

### 6.2 客户详情

扩展 `GET /api/customers/:id`，返回完整的非敏感交接档案和现有 2026 服务统计。长文本、链接和多选数组保留结构化形态。

### 6.3 同步与待关联

- `GET /api/handoff-sync/status`
- `POST /api/handoff-sync`
- `GET /api/handoff-profiles/unmatched`
- `PATCH /api/handoff-profiles/:id/link`

同步和手动关联仅管理员或经理可执行。

### 6.4 敏感查看

- `POST /api/handoff-profiles/:id/secrets/:field/reveal`

接口仅允许管理员访问，返回单一字段且禁止缓存，并写入审计记录。普通客户详情接口永远不返回敏感原文。

## 7. 客户中心页面

客户中心继续作为统一入口，不新增一级导航。

### 7.1 顶部概览

显示：

- 客户总数
- 已交接客户数
- 待交接客户数
- 待关联记录数
- 存在遗留问题的客户数

### 7.2 筛选与列表

筛选项包括：

- 关键词
- 全部 / 已交接 / 待交接 / 待关联
- 交接状态
- 部署方式
- 是否存在遗留问题

列表主列为：客户、部署方式、交接人、交接时间、交接状态、遗留问题、2026 服务量。遗留问题只显示是否存在和简短摘要，不在列表展开长文本。

### 7.3 客户详情

在现有客户详情中增加交接档案区域：

1. 交接概览
2. 部署方式、站点和部署清单
3. 功能使用情况
4. 日志、APM 和 RUM 接入
5. 非标操作或特别开发功能
6. 重要历史问题
7. 遗留问题
8. 沟通渠道与对接人
9. 2026 服务统计与服务记录

缺失字段统一显示“未填写”；多选值使用标签；长文本支持展开；合法飞书和 HTTPS 链接可直接打开。敏感内容显示为掩码，管理员通过独立操作查看。

## 8. 滚动与浮层修复

### 8.1 根因

当前 `.app-shell` 仅设置 `min-height: 100vh`，主内容没有视口高度和内部滚动边界。客户页一次加载 100 条记录，因此内容直接撑高 `body`，浏览器整体滚动。

同时，客户弹窗、导入弹窗、服务记录抽屉和 Toast 都渲染在带 `transform` 动画的 `.page-stack` 内。带变换的祖先会影响 `position: fixed` 的包含块，使浮层可能相对长页面定位，从而出现弹窗位于页面下方的问题。

### 8.2 应用壳

- 桌面端将应用壳固定为 `height: 100dvh`，并设置 `overflow: hidden`。
- 左侧导航固定在壳内，不参与业务内容滚动。
- 主区域使用行布局：固定顶部标题栏 + 可用高度内的路由内容。
- 客户页操作区固定在客户模块上方。
- 企业客户档案卡片使用 `min-height: 0` 和内部 `overflow: auto`。
- 表头使用 `position: sticky`，纵向滚动时保持可见。
- 窄屏表格在卡片内部横向滚动，不扩张 `body`。
- 移动端保留自然页面滚动，避免双滚动区域影响触屏操作。

### 8.3 浮层统一

- 所有对话框、抽屉和 Toast 使用 Vue `Teleport` 挂载到 `body`。
- 浮层始终相对视口定位，不受页面动画或滚动容器影响。
- 打开浮层时锁定背景滚动，关闭后恢复。
- 支持 ESC 关闭、点击遮罩关闭、初始焦点和关闭后的焦点恢复。
- 对话框自身内容超过视口时，仅对话框内部滚动。
- 统一检查并修复客户新建、客户导入、服务问题弹窗、服务记录抽屉和 Toast。

## 9. 错误处理与可观察性

- 飞书 token、权限、限流、网络和解析错误使用明确且脱敏的同步状态。
- 同步页面展示最后成功时间、读取数、变更数和失败摘要。
- 客户列表或详情读取失败不影响其他模块，提供重试入口。
- 待关联记录不会计入已交接客户数。
- 敏感信息识别或加密失败时，该字段不落库，并将记录标为失败，禁止降级为明文保存。

## 10. 测试与验收

### 10.1 后端

- 飞书应用 token、分页和失败重试测试。
- 20 个真实字段形态的映射测试。
- 每日完整同步的幂等、软删除和失败保护测试。
- 客户名称唯一匹配、无匹配、多候选和手动覆盖测试。
- 敏感信息识别、加密、脱敏、权限和审计测试。
- 客户列表筛选与客户详情聚合测试。

### 10.2 前端

- 客户列表交接汇总、筛选、空状态和错误状态测试。
- 客户详情各字段组、长文本、多选值和链接展示测试。
- 普通角色不可查看敏感字段，管理员查看后关闭即清理状态。
- 弹窗和抽屉 Teleport、ESC、焦点恢复与背景锁定测试。

### 10.3 浏览器验收

- 桌面端整页无纵向滚动，只有企业客户档案列表内部滚动。
- 列表滚动时表头保持可见，侧边栏、顶部标题和操作区保持固定。
- 在列表滚动到任意位置后打开新建和导入弹窗，弹窗始终在当前视口居中。
- 服务记录抽屉和 Toast 不受页面滚动位置影响。
- 39 条交接记录全部同步；现有 96 家客户不被删除；已交接、待交接和待关联统计符合关联结果。
- 抽查飞书中的多选、富文本、链接、日期和人员字段，系统展示不丢失。
- 普通账号无法获得敏感原文，管理员查看行为有审计记录。

## 11. 发布策略

1. 备份生产 MySQL。
2. 部署数据库迁移和后端代码，配置交接表及加密环境变量。
3. 执行首次完整同步并核对 39 条记录及关联结果。
4. 部署前端并完成桌面端和移动端滚动、弹窗验收。
5. 观察首次定时同步和服务日志。
6. 验证通过后推送 `main` 到远程仓库并保持工作树干净。
